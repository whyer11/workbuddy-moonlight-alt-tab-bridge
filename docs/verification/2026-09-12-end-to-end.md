# 2026-09-12 真机验收记录

## 环境

- Pad：小米 Pad M367FC，Android 17 / HyperOS 4
- Moonlight：12.1
- 串流目标：3408×2272、144 FPS
- 主机：Windows + Sunshine

## 可行性验证

- HyperOS 即使关闭原生“切换应用 Alt Tab”，仍会在应用前处理或吞掉 Tab；Moonlight 无法直接收到完整组合键。
- 辅助功能服务已成功绑定并申请键盘过滤，但真机物理 Alt+Tab 不会回调到服务；最终 APK 已完全移除辅助功能组件。
- `/dev/input/event9` 名称为 `Xiaomi Keyboard`；ADB shell 能成功执行 `EVIOCGRAB`，也能使用 `/dev/uinput` 创建虚拟键盘。
- Moonlight 12.1 真机验证可转发 F12，但不支持最初试验的 F13，因此最终映射为 `Alt+F12`。

## 自动验证结果

- `key_remap_test`：通过。覆盖普通 Tab、左右 Alt、重复事件以及 Alt 先于 Tab 松开的序列。
- ARM64 原生桥接：使用 NDK 29、`-Wall -Wextra -Werror` 从源码构建成功。
- Windows 主机：使用 MinGW、`-Wall -Wextra -Werror` 从源码构建成功；`--probe` 返回 0，实际合成 `Alt+F12` 后日志记录 `HOTKEY_TRIGGERED send=TAB_OK`。
- Android APK：0.5.0，APK Signature Scheme v2/v3 验证通过，zipalign 验证通过。
- APK 请求权限只有 `RECEIVE_BOOT_COMPLETED` 与 Shizuku API 权限；没有辅助功能、网络或存储权限。
- APK 内置原生桥接 SHA-256 与 Pad 上部署文件一致：`B76537B487F46621D00FBC357F7772085C57C319EC98A23C8BA2A9577DB110AA`。
- 最终 APK SHA-256：`D1FE5C21B80BAD1F2806A76F8CE04B11336ABC7E4ADED31173A12B19534049E5`。
- Windows 最终程序 SHA-256：`44494C363454B7C3E38B6B1606B991B1B7883672BE8B563B6B58BD17E5EA20D9`。

## 运行态与持久化

- Shizuku 13.6.0 以 shell 身份运行，`WRITE_SECURE_SETTINGS` 已授权。
- WorkBuddy 的 Shizuku 权限为“始终允许”。
- 0.4.0→0.5.0 热升级后旧 UserService 正常退出；系统中只有一个 UserService 和一个原生桥接进程。
- HyperOS 自启动管理现场复查：Shizuku 与 WorkBuddy Alt+Tab 两项均为开启。
- Windows HKCU Run 登录项存在，指向最终程序；隐藏常驻进程正在运行。
- 未执行 Pad 冷重启，因为设备配置了 PIN，重启后需要用户现场解锁。开机广播、自启动权限、Shizuku 官方 Android 13+ ADB 自启动条件均已配置和静态核验。

## 端到端结果

用户在实际 Moonlight 会话中使用 Pad 实体键盘按下 `Alt+Tab` 后，Windows 任务切换界面成功出现。Windows 日志同时记录多次 `HOTKEY_TRIGGERED send=TAB_OK`，证明完整路径为：物理键盘 → evdev/uinput 映射 → Moonlight `Alt+F12` → Windows 常驻程序 → Windows `Alt+Tab`。
