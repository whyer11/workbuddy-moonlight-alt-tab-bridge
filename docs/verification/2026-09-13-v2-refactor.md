# WorkBuddy 键盘桥接 0.7.0 架构重构验收

## 架构结果

- `protocol/bridge-schema.json` 是产品版本、协议版本、端口和规则能力的唯一来源；生成 Java 与两端 C 头文件，并由一致性测试逐字节校验。
- Android 分为 `domain`、`ports`、`adapters`、`application`、`nativebridge`、`shizuku` 和 UI。状态归约按每条规则实际能力计算，不再由 Java 目录伪造原生能力。
- 原生程序提供无设备副作用的 `--describe`，运行成功后输出严格的 `WB_NATIVE_READY_V2`。Pad 部署使用 `.new/.previous`、SHA-256、能力校验和恢复事务。
- Pad 与电脑状态探测分别使用单线程隔离执行器和共享截止时间；任一端卡住不会占用另一端的执行资源。重复刷新会合并，页面停止后不再回调。
- Windows `KeyboardBridgeCore`、`HostApplication` 与 UDP `WorkBuddyStatusServer` 分离。实测占用 UDP 57420 后 `--probe` 仍返回 0，证明状态服务降级不再关闭键盘核心。
- 兼容模式仍保持全局拦截，因为当前 Moonlight 输入路径尚未证明稳定携带可识别的 injected 标志；Pad 页面新增显式暂停/恢复开关。

- 运行态只有一个应用进程、一个 Shizuku UserService 和一个 `alttab_evdev_bridge`。`--describe` 返回 `version=0.7.0 protocol=2 rules=alt_tab,windows_key,arrow_keys`。
- 页面显示“全链路正常”；Alt+Tab 与 Command 规则均为 Pad/电脑端运行中，方向键为 Pad 端运行中/电脑端无需桥接。
